# SEO guidance, late 2026

Research date: 2026-11-20. Source-type marks: **[D]** = engine or standards documentation, **[3P]** = third-party study or press, **[Inf]** = inference by the researcher.

**The main correction:** the PRD §10 plan rests on two rich results that no longer exist. FAQ rich results stopped showing on 2026-05-07, and HowTo rich results went away in 2023. The `SoftwareApplication` rich result also requires `aggregateRating` or `review`, which this site doesn't have. Google's May 2026 AI guide adds that AI Overviews and AI Mode need no special files or markup: it comes down to indexability, a snippet-eligible page, original content, and the new Search Console setting for generative AI.

## B. Implementation checklist (highest impact first)

1. **Indexability.** Every indexable page returns 200, has a self-referencing absolute canonical with no trailing slash, and has no `noindex`. `/404` returns a real 404. A trailing-slash URL gets a 301 to the version without it, in nginx.
2. **hreflang, in `<head>`, identical on both versions of a page:** `es` → `/x`, `en` → `/en/x`, and `x-default` → one of them. All three methods (head, header, sitemap) are equivalent, so use just one [D]. Use `es`, not `es-ES`, to target all Spanish speakers; a region-only code is invalid [D]. Canonicals stay self-referencing per language and never point across languages. Choosing `x-default`: English serves people whose browser is in neither language [Inf]; Spanish matches the PRD's priority. That one is a product decision.
3. **robots.txt:**

   ```
   User-agent: *
   Allow: /

   User-agent: Googlebot
   User-agent: Bingbot
   User-agent: OAI-SearchBot
   User-agent: GPTBot
   User-agent: ChatGPT-User
   User-agent: ClaudeBot
   User-agent: Claude-SearchBot
   User-agent: Claude-User
   User-agent: PerplexityBot
   User-agent: Perplexity-User
   User-agent: Google-Extended
   Allow: /

   Sitemap: https://<domain>/sitemap-index.xml
   ```

   Don't block `/_astro/` (CSS and JS are needed for rendering). The search bots are what get you cited: OAI-SearchBot, Claude-SearchBot, PerplexityBot. GPTBot and ClaudeBot are for training [D].
4. **Search Console** (domain property): submit the sitemap and turn on the generative-AI inclusion setting. **Bing Webmaster Tools**: import from Search Console, then enable IndexNow. Generate a key file `/<key>.txt` and POST the changed URLs to `api.indexnow.org` from CI after each deploy. Google doesn't use IndexNow.
5. **Sitemap.** Only indexable canonical URLs. Set `<lastmod>` only from a real content change (git commit date of the source file), never the build time. Google ignores `priority` and `changefreq` [D], so leave them out.
6. **Meta on every page:** `<html lang="es">` or `lang="en"`; `<meta name="robots" content="max-image-preview:large">`; a unique `<title>` and `<meta name="description">`; `og:title`, `og:description`, `og:url` (the canonical), `og:type`, `og:site_name`, `og:locale` plus `og:locale:alternate`, `og:image` as an absolute URL to a 1200×630 PNG or JPEG under 300 KB, with `og:image:width`, `og:image:height` and `og:image:alt`; and `twitter:card=summary_large_image`.
7. **JSON-LD (one `@graph` per page):**
   - Home only: `WebSite` {name: "PlexusTyping", alternateName, url, inLanguage} and `Organization` {name, url, logo (at least 112×112), sameAs: [GitHub repo, GitHub org]}.
   - `/descargar` and home: `SoftwareApplication` {name, applicationCategory: "EducationalApplication", operatingSystem: "Linux, Windows", offers {price: "0", priceCurrency: "EUR"}, softwareVersion, datePublished (the release date), downloadUrl, license (SPDX URL), screenshot, featureList, sameAs/codeRepository}. No `aggregateRating`.
   - Docs: `TechArticle` {headline, description, inLanguage, datePublished, dateModified, author → Organization or Person, publisher, isPartOf}.
   - Docs and feature pages: `BreadcrumbList`.
   - Validate every page in CI against schema.org, and spot-check in the Rich Results Test.
8. **Headers.** HTML: `Cache-Control: public, max-age=0, must-revalidate`, never `no-store`, which blocks bfcache. Images under `/og/`, plus favicons and the logo: `Cross-Origin-Resource-Policy: cross-origin`. Make sure CSP, HSTS and COOP don't give bots a 403 (bots fetch with no cookies). `X-Robots-Tag: noindex` on `llms*.txt` is optional.
9. **Performance on a static site.** Use cross-document view transitions in CSS (`@view-transition { navigation: auto; }`) instead of Astro's ClientRouter, which adds JS. Use a Speculation Rules `<script type="speculationrules">` with `prefetch` and moderate eagerness on internal links; it needs a CSP hash. Keep pages bfcache-eligible: no `unload` handlers, no `no-store`.
10. **Favicon.** Put `/favicon.ico` plus a PNG at least 48×48 (a multiple of 48) in `<link rel="icon">`, on the root and crawlable.
11. **llms.txt**, generated from the docs collection at build time. Optional: a `.md` mirror per doc page, linked with `<link rel="alternate" type="text/markdown">`.
12. **Release freshness.** Each release triggers a rebuild that updates `softwareVersion`, `dateModified`, `/novedades`, the RSS feed, and an IndexNow ping.

## C. On-page SEO (2026 guidance)

- **Titles.** There's no length limit, but Google truncates to the device width. It builds title links from `<title>`, the `<h1>`, `og:title`, anchor text and `WebSite` data, and rewrites boilerplate, mismatched or overlong titles [D title-link]. Rule: put the main term first, then " · PlexusTyping"; make it unique and in the page's language; keep the `<title>` aligned with the `<h1>`. The PRD's ~60 characters is a good heuristic, not a rule.
- **Meta descriptions.** Google uses them only sometimes and has no length limit [D snippets]. Write a unique summary of about 120–155 characters with a concrete fact (free, Linux and Windows, open source).
- **Headings.** One visible `<h1>` matching the title intent. `h2` for sections and `h3` under them, never skipping a level. Google recommends semantic HTML [D AI guide]. Landmarks: `header`, `nav`, `main`, `footer`, with breadcrumbs in `nav aria-label`.
- **URL slugs.** Lowercase, hyphenated, ASCII without accents, short and in the page's language. This matches the PRD's `/descargar` and `/preguntas-frecuentes`. Google accepts UTF-8, but ASCII avoids percent-encoding [D url-structure].
- **First paragraph.** State what the page is and who it's for in plain words. No keyword stuffing.
- **Internal links.** Descriptive anchors ("motor adaptativo"), never "aquí". Each feature page links to its docs and back, and every page is reachable from the nav or an index. Breadcrumbs both visible and in `BreadcrumbList`.
- **Images.** Real `<img>` with `alt`, descriptive file names (`mapa-de-calor-teclado.avif`), and `width`/`height` [D image SEO]. Content stays in text, not baked into images [D ai-features].
- **Tables and lists.** Use real `<table>` and `<ol>`/`<ul>` for specs, comparisons and steps. They are easy to extract. That they help AI citation is [Inf]; Google states no ideal format.
- **Length.** "No ideal page length" [D]. Merge pages that can't stand alone (see §D).
- **Dates.** A visible "Actualizado: <date>" that matches `dateModified` [D publication-dates]. No future dates and no build dates.
- **Author and about.** The visible author (the project or a named maintainer) links to an About section and to GitHub, and the same author goes in `author`.

### Per-page template (each line is a CI check)

| Page | Required elements |
|---|---|
| All pages | lang; title; description; canonical; hreflang ×3; a single h1; robots `max-image-preview:large`; OG/Twitter set; landmarks; every img has alt and dimensions |
| Home | WebSite + Organization (sameAs); SoftwareApplication; version, licence, platforms, last release date as text; links to `/descargar`, `/funciones`, `/docs` |
| Feature | BreadcrumbList; h1 = feature; first paragraph says what it does and for whom; real screenshot with alt; link to its docs; visible "Actualizado" date |
| Download | SoftwareApplication with downloadUrl and softwareVersion; per-OS h2; SHA-256 values as text; system requirements as a table; release date |
| Docs | TechArticle with dates and author; BreadcrumbList; visible "Actualizado" and the app version it applies to; "Editar en GitHub" link; at least one internal link to a related feature |
| FAQ | Questions as h2/h3 or `<details>`, answers visible; FAQPage optional; each answer links to the matching doc |
| Release notes | One h2 per version with a `<time datetime>`; entries newest first; RSS link; release links to GitHub |

## D. Content rules for writers (10)

1. Write from first-hand product knowledge: real screenshots, real defaults, real limits. "Non-commodity content" is Google's first recommendation [D].
2. One page per real question or task. Don't make per-keyword page variants: that's scaled content abuse [D AI guide; spam policies].
3. Comparison pages ("alternativa a Monkeytype/keybr") need dated, checkable facts (platform, offline, licence, price), and a "checked on <date>" note for anything about the competitor. Say where they are better.
4. Write "web-based vs desktop" plainly. The "test de velocidad" results are browser tools, and a desktop app can't meet that intent directly.
5. Put the answer in the first paragraph, then the detail. Don't pad to a word count.
6. Keep spec facts (version, size, licence, OS) in text and sync them from release data, never hard-code them by hand.
7. Each doc page must solve something on its own. Merge pages under about 150 useful words into their parent [Inf; Google's statement is "no ideal length"].
8. Update `dateModified` only for meaningful changes.
9. Spanish first in natural Spanish (es-ES vocabulary is fine). English as a real translation, not machine output left unreviewed.
10. Don't pursue fake mentions, reviews or ratings [D AI guide "inauthentic mentions"]. Earn listings in roundup articles instead (see §E).

## E. Spanish keyword landscape (from SERPs only, no volumes)

Searches could only be run from the US, so these are not es-ES SERPs and should be checked there.

- **"curso de mecanografía gratis":** listicles (Genbeta, educaciontrespuntocero "42 programas", elgrupoinformatico "10 cursos"), course aggregators (Emagister, Alison, Great Learning) and TypingClub. Actions: pitch to the listicle publishers, and keep a structured lesson-path page.
- **"test de velocidad de escritura":** browser tools (Tidio, Coddy, TypingTop, TestGorilla). The intent is instant and in-browser. Use an explainer page (PPM, accuracy) that points to the app.
- **"mecanografía para programadores":** tools such as ttyper, Coddy code mode, typing.com, plus Platzi articles. Weaker competition and a strong fit for the code mode. This is the best candidate to target.

## F. Unverified or conflicting

- "INP is now 150 ms" (3P, April 2026) contradicts web.dev. Treat it as false until Google documents it.
- Whether Google-Extended affects AI Overviews: the docs don't say. Googlebot covers AI Overviews.
- The exact AIPREF robots.txt syntax is still a draft (vocab-08, attach-05), and Anthropic's page doesn't give the syntax.
- Google-Agent user-agent strings and IP files: only 3P summaries; Google's own page was not read.
- Platform support for AVIF and WebP in OG images: 3P sources disagree.
- CORP affecting scrapers: [Inf]. Server-side fetchers shouldn't enforce it; no primary source confirms this either way.
- The "Search Console generative-AI toggle" rollout: the June 2026 blog post says UK first. Whether it's global yet is unknown.
- Which search index Claude and Copilot use for citations: not documented publicly, so not claimed.
- The November 2026 core update is still rolling out (started 2026-11-10), so its effects are unknown.
- Spain-specific SERPs: not observed.
